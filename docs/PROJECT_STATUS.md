# ReStory: состояние проекта

Обновлено: 14.11.2026. Репозиторий: https://github.com/AzaKail/re-story

## 1. Что за проект

Кейс NASA Space Apps Challenge: «Abandoned but not Forgotten: Storytelling about NASA's Discarded Equipment on the Moon and Mars».

ReStory: сайт-музей в браузере. Посетитель видит космос с Луной и Марсом, на них отмечены аппараты NASA, которые там остались навсегда. Выбираешь аппарат: камера подлетает к месту, где он стоит, а «Узнать больше» открывает его страницу в музее. Справа внизу гид AIstronaut отвечает на вопросы.

Главная идея кейса: «очеловечить технику». Аппарат сам рассказывает, зачем его создали, что он пережил и почему замолчал.

Название ReStory соединяет три смысла: рассказать историю заново (re-story), вернуть её из забвения (restore) и саму историю (history).

## 2. Как запустить у себя

Нужны Python 3.12+, git, PostgreSQL. Для чата ещё Ollama.

1. Создать пустую базу `bd_re_story` в PostgreSQL.
2. Выполнить:
   ```
   git clone https://github.com/AzaKail/re-story.git
   cd re-story
   python -m venv .venv
   .venv\Scripts\activate            (macOS / Linux: source .venv/bin/activate)
   pip install -r requirements.txt
   copy .env.example .env            (macOS / Linux: cp .env.example .env)
   ```
3. В `.env` вписать пароль PostgreSQL в `DB_PASSWORD`.
4. Выполнить:
   ```
   python manage.py migrate            (заодно заполняет каталог аппаратов)
   python manage.py load_knowledge     (база знаний чата, нужна запущенная Ollama)
   python manage.py runserver
   ```
5. Открыть http://127.0.0.1:8000/. Адрес с `?lang=ru` или `?lang=kk` сразу открывает нужный язык, `#mars` открывает Марс.

Для чата: установить Ollama и скачать модели `ollama pull gemma4:e2b` и `ollama pull nomic-embed-text`.

После каждого `git pull`: `python manage.py migrate`, затем обновить страницу через Ctrl+F5.

Если `activate` пишет, что выполнение сценариев отключено: один раз выполнить `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

Открыть на телефоне в той же Wi-Fi сети: Wi-Fi в Windows должен быть «Частной сетью», сервер запускать командой `python manage.py runserver 0.0.0.0:8000`, на телефоне открыть `http://<IP ноутбука>:8000/` (IP показывает `ipconfig`).

## 3. Технологии

| Часть | Что используем |
|---|---|
| Сервер | Python, Django 5.2 |
| База данных | PostgreSQL, драйвер psycopg 3, pgvector (по возможности) |
| 3D | Three.js r170, лежит в проекте, без интернета и CDN |

| Показ | ноутбук с видеокартой, Wi-Fi на площадке есть |
| Данные | только NASA: SVS, Solar System Treks, GIBS, NASA Image and Video Library, NSSDCA, science.nasa.gov |

Палитра: чёрный `#000000` (фон), Prussian Blue `#14213d` (панели и карточки), оранжевый `#fca311` (акцент), Alabaster Grey `#e5e5e5` (текст), белый `#ffffff` (заголовки). Цвета заданы переменными в начале `static/css/main.css`.

## 5. Что уже сделано

**3D-космос**
- Звёзды, Солнце как источник света, Луна, Марс и Земля с картами NASA.
- Карты Луны и Марса в трёх размерах: 2k грузится сразу, детальная 8k (4k на телефоне) подгружается фоном только для текущей планеты.
- Вращение мышью и пальцами, медленное автовращение, которое останавливается, когда человек берёт управление.
- Переключатель Луна / Марс с перелётом камеры. Марс стоит далеко от Луны и Земли.
- Нельзя приблизиться ближе, чем вид на объект: ближе карта всё равно размыта.
- На фоне Меркурий, Венера, Юпитер, Сатурн, Уран, Нептун: настоящие фото NASA, всегда повёрнуты к экрану.
- Мягкая подсветка от камеры, чтобы объект было видно и на ночной стороне.

**Сценарий посетителя**
- Слева панель «Объекты» со списком аппаратов на этой планете (4 на Луне, 7 на Марсе). Её можно свернуть.
- Клик по объекту: камера подлетает по дуге к месту, где стоит аппарат, там оранжевая метка. Внизу полоска: «Узнать больше» и крестик (Esc тоже закрывает).
- «Узнать больше»: камера ныряет в точку, экран темнеет, открывается страница аппарата в музее.
- Музей: отдельный экран со своей прокруткой. Назад в 3D только кнопкой «3D-версия», камера поднимается обратно к аппарату.
- Клик по названию ReStory слева вверху открывает экран «О проекте».

**Страница аппарата в музее**
- Тип и тело, статус, место и даты.
- «Тогда и сейчас»: архивное фото и современный снимок места. Есть у 6 аппаратов: Apollo 11 (LRO), Viking 1, Opportunity, Phoenix, InSight (HiRISE), Ingenuity (ровер Perseverance). У остальных одно фото.
- Рассказ от первого лица, ключевые факты, сестринские миссии, источники NASA.
- «Спросить гида об этом аппарате»: открывает чат с готовым вопросом.
- Другие аппараты на этом теле (можно перейти, не выходя из музея) и рассказ о самом теле.

**«О проекте»**
- Задача, как пользоваться, какие данные NASA используются (со ссылками), команда.

**Языки**
- Переключатель EN / RU / KZ на всех экранах. Без перезагрузки, выбор запоминается. Чат переключается вместе с сайтом.

**Чат-бот AIstronaut**
- Ответы потоком, история в пределах вкладки, три языка.
- Отвечает только по базе знаний: тексты команды (`data/knowledge/`) и весь каталог аппаратов.
- Модель ответов на видеокарте, модель поиска на процессоре, «размышления» отключены, длина ответа ограничена.
- В админке можно загрузить сразу много файлов в базу знаний.

**Скорость и надёжность**
- Пока открыт музей или «О проекте», 3D не рисуется.
- Если кадров меньше 40 в секунду, качество картинки снижается автоматически.
- Three.js и все текстуры лежат в проекте, интернет на показе нужен только для фото в музее.
- Если фото не загрузилось, оно просто скрывается. Если 3D не может запуститься, вместо вечной заставки показывается сообщение.

## 6. Как работать с каталогом аппаратов

Все данные аппаратов лежат в одном файле: `data/artifacts.json`. Это единственный источник: панель, метки на планетах, музей и база знаний чата берут данные оттуда.

У каждого аппарата: код (например `apollo-11-lm`), тип, тело, координаты, даты, статус, краткое описание, рассказ от первого лица, ключевые факты, сестринские миссии, фото NASA (`image_url`), снимок «Сейчас» (`now_view`, необязательно), переводы на ru и kk (`translations`), источник.

После правки `data/artifacts.json`:
```
python manage.py seed_catalog          (обновить базу сайта)
python data/build_knowledge_base.py    (пересобрать тексты для чата)
python manage.py load_knowledge        (обновить базу знаний чата)
```

Править можно и в админке (`/admin/`), но тогда изменения останутся только в вашей базе. Чтобы они были у всех, правьте `data/artifacts.json` и коммитьте.

Чтобы добавить «Тогда и сейчас» аппарату, у которого его пока нет (Apollo 12, Surveyor 3, Apollo 15, Spirit, Sojourner): найти снимок места на images.nasa.gov и добавить поле `now_view` по образцу Apollo 11 в том же файле.

## 7. Что делаем дальше

1. **Автоэкскурсия:** камера сама перелетает от аппарата к аппарату (делает отдельный участник).
2. **Режим демо для ролика:** сайт сам показывает главное за 30 секунд, ролик записывается одним дублем.
3. **Проверка фактов:** каждую дату и цифру в `data/artifacts.json` сверить с NSSDCA и science.nasa.gov.
4. **Сдача:** 30-секундный ролик, описание проекта. В описании указать, как использовался ИИ: это требование правил Space Apps.
5. **По возможности:** подписи над аппаратами, дальний космос (Церера с Dawn, Эрос, Pioneer, Kepler).

## 8. Идеи на потом

- **«Последний сигнал».** Таймлайн аппарата: запуск, посадка, работа, тишина. Только проверенные даты. Честно помечаем мифы: фраза Opportunity «My battery is low and it's getting dark» на самом деле пересказ журналиста, а не сообщение ровера.
- **Таймлайн 1966-2024:** ползунок, аппараты появляются в год посадки и гаснут, когда замолкают.
- **Режим Artemis:** охранные зоны вокруг мест Apollo по рекомендациям NASA 2011 года.
- **«Оставить благодарность»:** общий счётчик у каждого аппарата.

## 9. Договорённости команды

- **Коды аппаратов** одни на всех, как в `data/artifacts.json`: например `apollo-11-lm`, `spirit-mer-a`, `ingenuity`. По ним связаны 3D, музей и чат.
- **Данные только NASA.** Каждая картинка и факт: строка в `docs/SOURCES.md` (откуда, лицензия, где используется). Ничего не выдумываем: нет источника, значит, поля нет.
- **3D-модели аппаратов не используем:** жюри не дало разрешения.
- **Тексты интерфейса** сразу на трёх языках. Английский главный. Строки интерфейса в `static/js/i18n.js`, у всех языков одинаковые ключи.
- **После каждого изменения** обновляется `docs/documentation.md` (на английском): что изменили, зачем, как пользоваться.
- **Секреты** (пароли, ключи) только в `.env`, он не попадает в git.

## 10. Риски и открытые вопросы

- **Ссылка для жюри.** Показ идёт с ноутбука. Если проект будут смотреть онлайн, нужна публичная версия или видео. Проверить правила сдачи на сайте Space Apps.
- **Чат на показе.** Перед выступлением один раз задать боту вопрос, чтобы модель загрузилась в память.
- **Поиск чата по-русски и по-казахски** слабее, чем по-английски. Решение известно (многоязычная модель поиска `bge-m3`), решает Дмитрий.
- **Казахский перевод** надо вычитать человеку, который хорошо знает язык.
- **Факты.** Одна ошибка в дате подрывает доверие жюри.
